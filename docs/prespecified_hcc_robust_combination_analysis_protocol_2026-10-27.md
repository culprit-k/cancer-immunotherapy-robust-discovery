# Prespecified analysis protocol: robust tumour–immune feature combinations in HCC

**Status:** protocol draft; no outcome analysis authorized until the data-linkage and input-compatibility gates below pass.  
**Version date:** 2026-10-27  
**Purpose:** prevent leakage, pseudoreplication, and post-hoc claims while testing whether combinations of spatial tumour–immune features generalize across HCC cohorts.

## 1. Research question and claim boundary

Can a prespecified AI workflow identify combinations of spatial protein features associated with immune-checkpoint-inhibitor (ICI) outcome in HCC that remain directionally and quantitatively stable across independent cohorts, beyond single-marker and clinical-only baselines?

This is an association and robustness question. Counterfactual perturbations generated by a model are **computational hypotheses**, not evidence that experimentally changing a marker causes immune escape. Causal wording requires independent mechanistic evidence.

## 2. Cohorts and analysis units

- Discovery cohort: public HCC spatial-imaging cohort (Zenodo record 10793609; 54-patient cohort described in the source study). Confirm the final eligible patient count from source metadata before analysis.
- External ICI cohort: public HCC ICI cohort (Zenodo record 10794904; 42 patients and 86 image ROIs reported by the source). The patient, ROI, clinical endpoint and image filename crosswalk must be authoritative.
- Primary statistical unit: **patient**, not ROI, cell, patch, or pixel.
- Multiple ROIs from one patient remain nested within that patient. Aggregate ROI-derived features using a rule fixed before outcome inspection, or use a hierarchical model with patient-level clustering.
- Known inventory discrepancy: the archive has 86 image/mask triplets while the clinical table contains 84 ROI entries. The documented extra image files associated with ICI_24 and ICI_39 are not yet authoritatively identified. Exclude affected patients from outcome analyses until the image-level crosswalk is resolved; do not silently choose files.

## 3. Hard pre-analysis gates

No model inference or outcome modelling until all gates have dated evidence:

1. **Data identity:** source URL/DOI, licence, archive checksum, exact filenames and immutable raw-data manifest.
2. **Patient/ROI crosswalk:** every included image maps to one patient and one documented ROI; discrepancies are resolved from source-authoritative records.
3. **Panel contract:** every image plane is mapped to the exact marker name and, where required, UniProt identifier; duplicates and missing mappings are reported.
4. **Mask semantics:** unique labels and frequencies, empty-mask behavior, representative image overlays, and documented meanings of cell/stromal/parenchymal labels. Never infer semantics from integer values alone.
5. **Input preprocessing:** either reproduce the official VirTues/Spora pipeline with its required marker mapping, statistics and filtering, or explicitly label a separately validated normalized-domain adaptation. The 0–1 range alone is not compatibility evidence.
6. **Checkpoint provenance:** pinned source revision, config, checkpoint SHA-256, licence, marker-embedding provenance and documented training-corpus exposure review. No weights committed to this repository.
7. **Outcome dictionary:** endpoint definition, event/censoring rules, follow-up time, treatment context, missingness and covariates sourced from the published clinical metadata.
8. **Analysis freeze:** commit the feature definitions, splits, metrics and candidate-generation settings before viewing external-cohort outcome associations.

Each gate is PASS / FAIL / UNKNOWN with evidence links. UNKNOWN is treated as FAIL for outcome analysis.

## 4. Proposed feature families

Use only features supported by the panel and mask semantics:
- Marker abundance/distribution summaries within verified tumour, stromal, and immune compartments.
- Pairwise or small-combination interaction features, with combinations restricted to a prespecified maximum size and regularized to limit search burden.
- Spatial co-localization/proximity features only if cell segmentation and coordinate conventions are validated.
- Model-derived reconstruction/residual features only after official input compatibility is established.

Do not describe a feature as a tumour-cell feature unless cell-to-compartment assignment is validated. Do not interpret a mask label as a specific cell type without source evidence.

## 5. Baselines and comparison

At minimum compare:
1. Clinical-only baseline using only predeclared, available covariates.
2. Single-marker models.
3. Regularized additive model using the same candidate feature pool.
4. Pairwise/small-combination model.
5. Proposed AI/counterfactual-ranking method.

Use identical patient-level splits and covariate availability across comparable models. Report the effective number of patients and events; do not treat ROIs or cells as independent outcome observations.

## 6. Leakage prevention and validation

- Split by patient, never by ROI or image tile.
- Keep all ROIs, cells and patches from a patient in the same fold.
- Fit normalization, imputation, feature selection, calibration and threshold selection using training data only.
- If the cohorts have distinct roles, freeze discovery-stage choices before evaluating the external ICI cohort.
- Do not use the external cohort to select markers, thresholds, preprocessing variants or model hyperparameters.
- If the same cohort contributes to model pretraining or method development, disclose it and do not call it independent validation.
- Report missing data and exclusions by patient and reason.

## 7. Primary metrics and robustness checks

Choose the primary endpoint and metric only after the endpoint dictionary is verified. For binary outcomes, candidate metrics include AUROC and AUPRC with patient-level bootstrap confidence intervals; for time-to-event outcomes, use a prespecified survival metric and censoring-aware analysis. Do not report a metric whose assumptions are not met.

Robustness checks:
- Patient-level bootstrap uncertainty.
- Leave-one-patient-out or repeated patient-level resampling within the development cohort, if sample size supports it.
- Stability of selected feature combinations across resamples (selection frequency and rank correlation).
- Sensitivity to documented alternative compartment aggregation rules, without selecting the most favorable result.
- Calibration and decision utility only if sample size and event count support them.
- Negative controls and permutation tests that preserve patient grouping.
- Comparison with single-marker and additive baselines to establish whether combinations add information.

All estimates must include uncertainty. A higher point estimate alone is not evidence of robust improvement.

## 8. Counterfactual interpretation

For each proposed combination:
- Define the intervention mathematically (what feature changes, what is held fixed, and what valid range applies).
- Check whether perturbed inputs remain within observed data support and preserve structural constraints.
- Distinguish model sensitivity from biological causation.
- Report uncertainty and sensitivity to the baseline/reference state.
- Do not translate an in-silico perturbation into a treatment recommendation.
- Treat experimentally testable mechanisms as hypotheses for later validation.

## 9. Reporting and go/no-go criteria

Proceed to manuscript-level claims only if:
- All hard gates pass;
- patient-level leakage controls are verified;
- the external evaluation is genuinely held out;
- the proposed method is compared against meaningful baselines;
- performance and feature stability are reported with uncertainty;
- limitations and negative findings are disclosed.

If the external cohort cannot support the planned endpoint or event count, reframe as a feasibility/methodological study rather than overfit a high-dimensional predictive model. If preprocessing compatibility cannot be established, do not call the work a VirTues reproduction.
